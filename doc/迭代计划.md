# 迭代计划

`hls-downloader` 的版本路线与优先级。优先级：P0 必须 > P1 应该 > P2 可选。

---

## V1.0 —— 核心下载（已完成）

- [x] yt-dlp + ffmpeg 封装，支持网页链接 / m3u8 直链
- [x] 加密 HLS（AES-128）自动解密 + 合并 MP4
- [x] 输出目录位置参数 + 默认 `downloads/`
- [x] 自动定位 yt-dlp / ffmpeg

## V1.1 —— 反爬 / 防盗链 / 登录态（已完成）

- [x] `--cookies` / `-b/--browser` 登录态（二选一）
- [x] `--ua/--user-agent` 覆盖 User-Agent
- [x] `-r/--referer` 防盗链 Referer
- [x] `--proxy` 代理
- [x] 参数对照文档、config 示例
- [x] 解决 `jav.sb` 类 Cloudflare Turnstile 站点的 `403`/`WinError 10054`（用浏览器登录态）

## V1.2 —— 配置与下载历史（本次，已完成）

- [x] `config.json` 读取（命令行 > config > 默认值）
- [x] 下载历史记录 `download_history.log`（默认开启，txt/log 可读格式）
- [x] 历史开关：config `history` / 命令行 `--no-history`
- [x] 自定义历史文件：config `history_file` / 命令行 `--history-file`
- [x] 功能清单、迭代计划文档

## V1.3 —— 登录态落地（本次，已完成）

- [x] `doc/cookies导出指南.md`：浏览器扩展导出 cookies.txt 的图文指引 + `cf_clearance` 绑定 UA+IP 说明
- [x] 各文档标注 `-b chrome` / `-b edge` 受 App-Bound Encryption（ABE）限制不可用（yt-dlp 官方无解）
- [x] 无登录平台回归测试：公开 HLS 流 `test-streams.mux.dev` 下载成功（478.94 MiB）
- [x] `--cookies` 自动识别 Cookie-Editor 的 JSON 导出并转 Netscape（登录态落地，FC2 登录墙复测通过、标题恢复）
- [x] 修下载历史把 ANSI 颜色码写进日志的小瑕疵

## V1.4 —— 文件名 / 去重 / 批量下载（本次，已完成）

- [x] `-o/--output <文件名>` 固定输出文件名（不含扩展名自动补 `.mp4`，已含扩展名则原样）
- [x] 同名文件去重：默认加序号 `名称 (1).mp4`，`--overwrite` 强制覆盖
- [x] `--batch <文件>` 批量下载：每行 `URL [文件名]`，`#` 注释与空行忽略，单条失败不中断

## V1.5 —— 下载失败重试队列（本次，已完成）

- [x] `--retries <次数>` 下载失败额外重试次数，默认 3（0 关闭重试）
- [x] 批量队列式重试：第一轮全跑，失败条目进队列统一重试
- [x] 重试耗尽仍失败的条目写脱敏清单 `failed_downloads.txt`（每行 `URL [文件名]`；含签名查询参数的 URL 需用原始链接重试）
- [x] 单条模式失败后额外重试 N 次，仍失败才报错

## V1.6 —— GUI 与打包（本次，已完成）

- [x] `gui.py`：tkinter 图形界面（核心下载 + 批量 + 代理），后台线程下载 + queue 回显，支持取消当前下载与关闭时优雅收尾
- [x] CLI 与 GUI 共用 `_run_single` / `_run_batch` 下载编排；`hls_download.py` 加 frozen 资源/数据目录区分（`RESOURCE_DIR` / `DATA_DIR`）
- [x] PyInstaller 打包（`build_cli.spec` / `build_gui.spec`），**onedir 文件夹分发**（含 ffmpeg + ffprobe，自包含，启动免解压）；CLI 双击无参数时进入交互式引导
- [x] pytest 回归测试覆盖参数/config、取消、临时 cookie、并发落盘和 GUI 生命周期，并接入发布工作流

## V1.12 —— 打包与发布工程化（本次，已完成）

- [x] GUI Worker 生命周期：去掉 30 秒强制关闭超时，请求停止后等 Worker `finally` 清理完再销毁窗口；Worker 改非 daemon
- [x] Cookie 安全清理：临时 cookie 只在 Worker 收尾后删除，关闭流程不再提前删
- [x] GUI 日志队列限流：队列固定容量、拥塞丢最旧普通日志、每轮限量消费、日志框保留 5000 行
- [x] Cookie JSON 字段校验：`domain` 拒绝空白与 `/`，`path` 必须 `/` 开头且不含控制字符
- [x] Windows 文件名安全处理：非法字符、路径分隔符、尾部空格/点、保留设备名统一清洗
- [x] URL 敏感参数脱敏：日志中的 `token` / `signature` / `credential` 等查询参数替换为 `REDACTED`
- [x] 控制台编码兜底：启动时把 stdout/stderr 切到 UTF-8（`errors=replace`），修掉非 UTF-8 控制台打印中文时的 `UnicodeEncodeError`（CI 冒烟暴露）
- [x] CLI / GUI spec 重构：`SPECPATH` 定位、独立 `--workpath`、不再删共享 `build/`，保留防叠加的产物目录清理
- [x] Portable 共享运行时 spec：`build_portable.spec` 输出 CLI + GUI 共用一个 `_internal` 的组合包
- [x] FFmpeg 完整版 / 精简版：`HLS_BUNDLE_FFMPEG` 开关；完整版缺 ffmpeg/ffprobe 时构建硬失败，Slim 版要求 PATH 同时有 ffmpeg 与 ffprobe
- [x] GitHub Actions 并行构建：test → prepare-ffmpeg → 四路并行构建 → release；依赖锁定 `requirements-build.txt`（v1.12.1 起改为 test 与 prepare 并行 + 三路构建，见下节）
- [x] SHA256 发布校验：FFmpeg 包校验 + 发布前 4 个 zip 解压校验 + 生成 `SHA256SUMS.txt`（v1.12.1 起为 3 个 zip）
- [x] 构建及发布文档：`BUILDING.md`、`requirements-build.txt`，并同步 README / 发布SOP / 代码地图

> lite 版 spec（`build_cli_lite.spec` / `build_gui_lite.spec`）已被 `HLS_BUNDLE_FFMPEG=0` + `build_portable.spec` 的 Portable Slim 方案取代，随 v1.12.0 移除。

## V1.12.1 —— CI 关键路径与发行资产优化（本次，已完成）

纯工程优化，不动下载核心、不裁 yt-dlp extractor、不减少发行模式（CLI / Portable / Portable Slim 三种仍在）。

- [x] `test` 与 `prepare-ffmpeg` 并行：FFmpeg 准备不再依赖测试结果，构建启动点从"测试 + 准备"叠加改为取两者较长值
- [x] 取消独立 `hls-downloader-gui.zip` 发行：`hls-downloader-portable.zip` 已包含 GUI + CLI + ffmpeg，独立 GUI 包属重复资产（98.8 MB）；`build_gui.spec` 保留供本地构建
- [x] 三路构建结构（build-cli / build-portable-full / build-portable-slim）替换四路，构建 job 数从 4 降到 3
- [x] release 校验从"恰好 4 个 zip"改为 3 个，`SHA256SUMS.txt` 随之只含 3 项
- [x] 记录耗时口径与基线：区分**关键路径**、**工作流墙钟**、**构建累计 Job 时间**，避免把累计时间当墙钟

## V1.12.1 之后（已验证暂不采用）

- **同 Runner 顺序构建 CLI + GUI 复用缓存**：实测跨 spec 无 TOC 复用（同 `--workpath` 下 GUI 仍 36.2 s，冷启约 40 s），合并 job 只省一次 checkout + 装依赖却损失并行，净亏，不采用。
- **继续增加并行 job 数**：v1.12.0 四路并行已让墙钟变长（178 s vs 139 s），瓶颈在关键路径与重复资产，不在并行度。

## 暂不做

- TLS 指纹伪装（curl_cffi impersonate）——对 Cloudflare Turnstile 无效，已评估不引入。
- DRM（Widevine/PlayReady）——超出 yt-dlp 能力范围。
