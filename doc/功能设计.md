# 功能设计

`hls-downloader` 的功能设计文档。记录「为什么这么设计」与「各模块怎么做」，是对 [功能清单.md](功能清单.md)（有哪些功能）的补充。

---

## 1. 目标与定位

一个**轻量命令行工具 + 可选 tkinter GUI**，用 yt-dlp + ffmpeg 封装，解决「加密 HLS（AES-128）视频下不动」的问题：

- IDM 抓到了 `.m3u8` 却报「由于法律原因，IDM无法下载此受保护的数据」——因为 IDM 不会解密。
- 本工具自动完成「抓 m3u8 → 下载分片 → 解密 → 合并成 MP4」，并保留源标题。
- 命令行是主力；`gui.py` 提供「核心下载 + 批量 + 代理」的用户友好界面（tkinter 标准库，无额外运行时依赖）。

**非目标**：不做 DRM（Widevine/PlayReady）。

---

## 2. 总体架构

两个入口 `hls_download.py`（CLI）+ `gui.py`（GUI），共用同一套模块级函数 + 一份可选的 `config.json` + 一份 `download_history.log`。

```
命令行参数 ──┐
             ├─► argparse 解析 ─► main() 合并优先级 ─► ydl_opts ─► yt_dlp.YoutubeDL
config.json ─┘                                                  └► ffmpeg（解密/合并）
gui.py ──► 后台线程 ─► hls_download._run_single/_run_batch ──► 同上
```

依赖均为「定位即用」，不要求装进 PATH：

| 依赖 | 定位优先级 |
|------|-----------|
| yt-dlp | 系统已装 > 脚本同目录 `ytdlp_lib/` > 上级目录 `ytdlp_lib/` |
| ffmpeg | 环境变量 `FFMPEG_LOCATION` > 脚本同目录 `ffmpeg*/bin/` > 上级目录 `ffmpeg*/bin/` |

> 设计理由：本机 `pip install`/conda/winget 易被代理污染卡死，故 yt-dlp 用 vendored 目录 + `sys.path.insert`，ffmpeg 用解压目录 glob 定位，避免依赖安装。

### 资源/数据目录区分（打包后）

源码运行与打包（单文件 onefile exe）后的目录语义不同，脚本顶部常量区分两者：

| 常量 | 源码运行 | 打包后（`FROZEN=True`） |
|------|---------|----------------------|
| `RESOURCE_DIR` | 脚本目录 `HERE` | PyInstaller `_MEIPASS`（解压临时目录，只读资源） |
| `DATA_DIR` | 脚本目录 `HERE` | exe 所在目录（可写，放 config/历史/失败清单/输出） |

- yt-dlp / ffmpeg 等只读资源从 `RESOURCE_DIR` 读；`config.json`、`download_history.log`、`failed_downloads.txt`、输出目录等可写数据默认落在 `DATA_DIR`。
- 相对路径（`out_dir`/`history_file`/cookies 等）以 `DATA_DIR` 为基准，保证打包后落在 exe 旁而非解压临时目录。

## 3. 模块划分

`hls_download.py` 的函数（全部为模块级小函数，无类）：

| 函数 | 职责 |
|------|------|
| `_find_ffmpeg_dir()` | 按优先级定位 ffmpeg 的 `bin` 目录，找不到返回 `None` |
| `_setup_ytdlp()` | 把 yt-dlp 加入 `sys.path`（系统优先，否则本地 lib），找不到则 `sys.exit` |
| `_load_config()` | 读同目录 `config.json`，缺失/损坏返回 `{}`（损坏打警告） |
| `_resolve_path(value, default)` | 把相对路径统一成以 `DATA_DIR`（脚本/ exe 所在目录）为基准的绝对路径 |
| `_strip_ansi(text)` | 去除 ANSI 颜色码，避免写进历史 |
| `_is_json_cookie_file(path)` | 判断 cookies 文件是否为 JSON |
| `_convert_json_cookies(src)` | JSON → Netscape 临时文件（返回路径或 None） |
| `_ensure_ext(name)` | 固定文件名补扩展名（无扩展名补 `.mp4`） |
| `_move_to_final(src, out_dir, overwrite)` | 下载完成后把 staging 里的成品移到输出目录（同名加序号 / 覆盖） |
| `_read_batch_file(path)` | 解析批量文件，返回 `[(url, 文件名或None), ...]` |
| `_retry_pending(download_one, pending, retries)` | 队列式重试：失败条目最多额外重试 `retries` 轮，返回（成功增数, 仍失败条目） |
| `_write_failed_list(path, items)` | 把重试耗尽仍失败的条目写成失败清单（每行 `URL [文件名]`） |
| `_format_history_line(entry)` | 把一条历史记录格式化成一行可读文本 |
| `_append_history(file, entry)` | 追加写历史（失败打警告不中断） |
| `_parse_args()` | argparse 解析，产出 `Namespace` |
| `_download_one(url, ...)` | 单条下载全流程（下载→落盘→记历史），批量循环复用，`log` 回调输出 |
| `_run_single(url, name, ...)` | 单条下载编排：失败额外重试 `retries` 次，返回 error（None=成功） |
| `_run_batch(items, ...)` | 批量下载编排：第一轮全跑→失败进队列重试→写失败清单，返回 (ok, fail, failed_file) |
| `main()` | CLI 编排：解析 → 读配置 → 定位依赖 → 合并优先级 → 构建 `ydl_opts` → 单条或批量下载 |

`gui.py` 的结构（一个类 + 两个辅助）：

| 组件 | 职责 |
|------|------|
| `_QueueLogHandler(logging.Handler)` | 把 yt-dlp 日志消息推入 queue，供主线程回显 |
| `_build_logger(q)` | 建带 queue handler 的 logger |
| `App.__init__/_build_ui` | 构建界面（URL 框 / 输出目录 / 文件名 / cookies / 代理 / 开始停止按钮 / 日志框） |
| `App._poll_queue` | 主线程统一消费队列：str=日志、`__status__`=状态栏、`__error__`=弹框 |
| `App._start/_stop` | 起/停后台下载线程（`stop_evt` 尽力停止） |
| `App._download` | 后台线程：定位依赖→建 ydl_opts→逐条调 `h._run_single`，只 `q.put` 不碰 tk 组件 |
| `main()` | `tk.Tk()` + `App(root)` + `root.mainloop()` |

## 4. 参数与配置合并（优先级）

**优先级：命令行参数 > config.json > 内置默认值。**

- `config.json` 的键名与命令行长参数名一致：`out_dir` / `cookies` / `browser` / `user_agent` / `referer` / `proxy` / `retries` / `history` / `history_file`。
- 合并规则：`args.X or config.get("X")`，即命令行缺省时回落到 config，再回落到内置默认值。
- `cookies` 与 `browser` 为互斥（二选一），且**跨来源**也互斥：命令行给了 `--cookies`、config 给了 `browser`，同样直接 `sys.exit` 报错，避免歧义。

### yt-dlp 映射

| 本工具参数 | yt-dlp 键 |
|-----------|-----------|
| `--cookies` | `cookiefile`（JSON 时先自动转 Netscape 临时文件） |
| `-b/--browser` | `cookiesfrombrowser=(名,)` |
| `--ua` / `--referer` | 合并进 `http_headers` 的 `User-Agent` / `Referer` |
| `--proxy` | `proxy` |
| `--retries` | （脚本内重试，不直接映射 yt-dlp；yt-dlp 自身 `retries`/`fragment_retries` 仍固定为 10） |
| `-o/--output` | `outtmpl`（固定文件名，先落 staging） |
| `out_dir` | 拼进 `outtmpl` |

## 5. 输出与历史记录设计

### 输出模板

- 默认 `outtmpl = <out_dir>/%(title).180B [%(id)s].%(ext)s`。
- 传 `-o/--output` 或批量行内文件名时，改用固定文件名，先下载到 `out_dir` 下的 staging 目录，完成后移动到 `out_dir`（同名加序号 / `--overwrite` 覆盖）。
- `%(title).180B`：标题按字节截断到 180，避免超长文件名。
- `format=best` + `merge_output_format=mp4`：m3u8 多为音视频混合 TS，用 best 最稳，ffmpeg 转封装成 mp4。
- `concurrent_fragment_downloads=16` + `retries=10` + `fragment_retries=10`：并发分片 + 自动重试。

### 去重落盘（staging）

1. 下载到 `out_dir` 下临时目录（`tempfile.mkdtemp` 前缀 `.hls_staging_`，同盘可原子 rename）。
2. 完成后取最终文件名，移到 `out_dir`：目标不存在→原名；已存在→加序号 `名称 (1).mp4`；`--overwrite`→`os.replace` 覆盖。
3. 历史记录写最终落盘路径；`finally` 清理 staging。

### 下载历史

- 默认开启，每次下载（成功/失败）向 `download_history.log` 追加**一行可读文本**（非 JSON，便于 `tail`/`grep` 直接看）。
- 行格式：`时间 [成功|失败] 标题 (id=xxx) | url | 文件路径或错误信息`。
- 开关：config `history: false` 全局关，`--no-history` 单次关。
- 路径：config `history_file` 或 `--history-file`，默认脚本同目录。
- 写入失败只打警告，不中断下载（历史是旁路，不应影响主流程）。

## 6. 关键设计决策

| 决策 | 理由 |
|------|------|
| 单文件、无类 | 工具规模小，模块级函数足够；无状态共享，避免引入不必要的抽象 |
| 依赖「定位即用」不进 PATH | 规避本机 pip/conda 被代理污染；vendored ytdlp_lib + glob ffmpeg |
| 历史用可读 log 而非 JSONL | 用户要「txt/log 格式、默认开启」；可读性优先于机器可解析 |
| 历史写入失败不中断 | 下载是主任务，历史是旁路，失败只告警 |
| cookies/browser 跨来源互斥 | 命令行与 config 交叉同时给会歧义，直接报错最安全 |
| `--cookies` 自动识别 JSON | Cookie-Editor 等导出 JSON，yt-dlp 只认 Netscape；脚本自动转临时文件，下载后清理 |
| 去重落盘用 staging + 原子 move | 下载到同盘临时目录再 move，避免同名覆盖竞态；同名加序号、`--overwrite` 覆盖 |
| 批量单条失败不中断 | 批量任务之间无依赖，单条失败记历史继续，最后汇总 |
| 失败重试队列（批量） | 第一轮全跑，失败条目进队列统一重试最多 `retries` 轮，耗尽写 `failed_downloads.txt` 可回喂 `--batch`；快的条目不被慢的卡住 |
| 单条失败额外重试后仍失败才报错 | 保持单条「失败即报错」的语义，但给 N 次自动重试机会 |
| 不做 curl_cffi impersonate | 已评估对 Cloudflare Turnstile JS 挑战无效（curl_cffi 不执行 JS） |
| GUI 用 tkinter + 后台线程 + queue 回显 | 标准库零额外运行时依赖；下载在 daemon 线程跑、`q.put` 消息由 `root.after` 回主线程刷新，避免冻结 UI / 跨线程碰 tk 组件 |
| CLI 与 GUI 共用 `_run_single`/`_run_batch` | 下载编排只写一份，GUI 复用，`log` 回调接 `queue` |

## 7. 数据流（下载成功/失败）

```
main()
  └─ _parse_args() → args
  └─ _load_config() → config
  └─ _setup_ytdlp() → 保证 yt_dlp 可导入
  └─ _find_ffmpeg_dir() → ffmpeg_dir（找不到则退出）
  └─ 合并参数 → ydl_opts
  └─ 单条：_download_one(url, ...)（失败额外重试 retries 次，仍失败才 re-raise）
  └─ 批量：
        ├─ 第一轮循环 _read_batch_file() 每条，打印 [i/N] 进度
        ├─ 失败条目进 pending 队列 → _retry_pending() 最多 retries 轮
        └─ 仍失败 → _write_failed_list() 写 failed_downloads.txt，汇总成功/失败数
  └─ _download_one：
        with yt_dlp.YoutubeDL(ydl_opts) as ydl:
            info = ydl.extract_info(url=..., download=True)
        ├─ 成功：_move_to_final(staging → out_dir) → 打印 → entry(status=success)
        └─ 失败：except Exception → entry(status=failed, error=...) → 记历史 → （单条 re-raise / 批量继续）
        └─ finally：清理 staging
  └─ _append_history(history_file, entry)（若 history_enabled）
```
