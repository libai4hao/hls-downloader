# 下载指南

加密 HLS 视频下载的完整操作指南。核心工具是 [hls_download.py](../hls_download.py)（yt-dlp + ffmpeg 封装）。

---

## 一、为什么 IDM 会报「版权受限」

IDM 抓到了 `.m3u8` 链接，但下载时报：

> 由于法律原因，IDM无法下载此受保护的数据

**真正原因**：这不是法律限制，而是 IDM 无法解密。视频是 **AES-128 加密的 HLS 流**——m3u8 里有一行：

```
#EXT-X-KEY:METHOD=AES-128,URI="xxx.ts",IV=0x...
```

每个 `.ts` 分片都被 AES-128 加密了，IDM 只会原样下载、不会解密，所以报错。

**解法**：换用会解密的下载器（yt-dlp + ffmpeg / N_m3u8DL-RE / 纯 Python 手写）。

---

## 二、标准操作步骤

### 第 1 步：准备依赖（一次性）

| 依赖 | 获取方式 |
|------|----------|
| Python 3.11+ | `python` 在 PATH 即可 |
| yt-dlp | 系统已装则直接用；否则把 `ytdlp_lib/` 放到脚本同目录/上级目录 |
| ffmpeg | 解压到脚本同目录或上级目录（形如 `ffmpeg-xxx/bin/`），或设环境变量 `FFMPEG_LOCATION` 指向 `bin` |

脚本会自动定位 yt-dlp 和 ffmpeg，无需手动设 PATH。

### 第 2 步：拿到链接

**优先用「网页链接」**（标题最准）：

```
python hls_download.py "https://www.example.com/video/xxx"
```

**需要登录态 / 过 Cloudflare 验证的站点**（如 `jav.sb`）：先按 [cookies导出指南.md](cookies导出指南.md)
导出 `cookies.txt`，再 `--cookies` 喂给脚本。

**没有网页链接时用 m3u8 直链**（从 IDM / 浏览器 F12 抓）：

```
python hls_download.py "https://cdn.example.com/hls/xxx.m3u8"
```

**需要防盗链信息（Referer/Cookie/UA）时**：

```
python hls_download.py "https://cdn.example.com/hls/xxx.m3u8" ^
  -r "https://www.example.com/" ^
  --cookies "cookies.txt" ^
  --ua "Mozilla/5.0 ..."
```

或用浏览器登录态（自动读 cookie，站点需登录时最省事）：

```
python hls_download.py "https://www.example.com/video/xxx" -b firefox
```

> 注意：`-b chrome` / `-b edge` 在本机 Chrome 156 + Edge（均开启 App-Bound Encryption）下
> **不可用**，会报 `Could not copy Chrome cookie database`，且 yt-dlp 官方无解（[yt-dlp#15401](https://github.com/yt-dlp/yt-dlp/issues/15401)）。
> 登录态请优先用 [cookies导出指南.md](cookies导出指南.md) 的 `--cookies` 方案；`-b` 仅对 Firefox 等非 Chromium 浏览器可用。

> 提示：URL 里含 `&` 时必须加双引号；CMD 里换行用 `^`，PowerShell 里用反引号 `` ` ``。

### 第 3 步：等待完成

输出 `<标题> [<id>].mp4`。省略输出目录时落到脚本同目录的 `downloads/`。

## 常用参数速览

| 场景 | 命令 |
|------|------|
| 指定输出目录 | `python hls_download.py "URL" "D:\下载"`（位置参数，直接跟在 URL 后） |
| 读 cookies 文件 | `--cookies cookies.txt`（也支持 Cookie-Editor 的 JSON，自动识别） |

| 指定历史文件 | `--history-file "D:\logs\dl.log"` |

完整参数 ↔ yt-dlp 映射与示例见 [参数对照.md](参数对照.md)。

## 配置与下载历史

**配置**：把 [config.example.json](../config.example.json) 复制为脚本同目录的 `config.json`，
脚本启动时自动读取。字段均可省略，省略时用默认值；命令行参数 > config.json > 默认值。

| config 字段 | 对应命令行参数 | 说明 |
|-------------|---------------|------|
| `out_dir` | 位置参数 `out_dir` | 输出目录（相对路径以脚本目录为基准） |
| `cookies` | `--cookies` | cookies 文件路径（Netscape cookies.txt 或 Cookie-Editor 的 JSON，自动识别） |
| `browser` | `-b/--browser` | 浏览器名（与 cookies 二选一） |
| `user_agent` | `--ua/--user-agent` | User-Agent |
| `referer` | `-r/--referer` | Referer |
| `proxy` | `--proxy` | 代理 |
| `history` | `--no-history`（反向） | `false` 关闭历史记录 |
| `history_file` | `--history-file` | 历史文件路径 |

**下载历史**：默认每次下载（成功/失败）追加一行可读文本到脚本同目录 `download_history.log`（txt/log 格式）。
每行形如 `时间 [成功/失败] 标题 (id=xxx) | url | 文件路径或错误信息`。

## 三、报错速查

| 现象 | 原因 | 处理 |
|------|------|------|
| `403 Forbidden` | 需要 Referer/Cookie/UA | 浏览器 F12→Network 找到 m3u8 请求 → 右键 Copy as cURL → 把 `Referer:`、`Cookie:`、`User-Agent:` 对应到 `-r` / `--cookies` / `--ua` |
| `Could not copy Chrome cookie database` | 新版 Chrome/Edge 用 App-Bound Encryption，yt-dlp 无法解密（官方无解） | 改用扩展导出 cookies.txt 后 `--cookies`，见 [cookies导出指南.md](cookies导出指南.md) |
| `Unsupported URL` | 链接不完整/过期 | 重新抓一次 m3u8（token 会过期） |
| `找不到 ffmpeg` | ffmpeg 不在预期位置 | 设环境变量 `FFMPEG_LOCATION` 指向 ffmpeg 的 `bin` 目录（如 `FFMPEG_LOCATION=C:\ffmpeg\bin`） |
| 分片下载中途失败 | 网络波动 | 脚本已带 `retries=10`、`fragment_retries=10` 自动重试 |
| `MemoryError` / 崩溃在 50% 左右 | 并发解密分片过多，内存峰值超限（大文件尤其） | 把 `concurrent_fragment_downloads` 降到 4；yt-dlp 会自动断点续传，重跑即可接着下 |
| 下载成功但无法播放 | 部分分片丢/损坏 | 用 `../examples/` 里的 `refill.py` 思路校验补齐 |

### 带 header 的下载写法

当站点校验 Referer/Cookie 时，优先用命令行参数（不必改代码）：

```bat
python hls_download.py "https://cdn.example.com/hls/xxx.m3u8" ^
  -r "https://www.example.com/" ^
  --cookies "cookies.txt" ^
  --ua "Mozilla/5.0 ..."
```

或直接在 `hls_download.py` 的 `ydl_opts` 里加：

```python
"http_headers": {
    "User-Agent": "Mozilla/5.0 ...",
    "Referer": "https://www.example.com/",
    "Cookie": "从浏览器复制",
}
```

## 四、IDM 抓不到链接时的兜底方案

如果 IDM 根本没抓到 m3u8（视频由 JS 动态加载、或藏在 iframe 里）：

1. **浏览器 F12 → Network → 过滤 `m3u8`**：播放视频，看列表里出现的 `.m3u8` 请求，右键 Copy link address 就是直链。
2. **过滤 `mp4` / `ts`**：有些站不用 m3u8 而是直接 mp4 分片，抓到后同样喂给脚本。
3. **如果 m3u8 是变体（master）**：主 m3u8 里只有多个分辨率的子 m3u8 地址，yt-dlp 会自动选，直接喂主 m3u8 即可。
4. **如果 F12 里也看不到**：可能是 DRM（Widevine/PlayReady，`#EXT-X-KEY:METHOD=SAMPLE-AES` 或 `drm`）。这种情况 yt-dlp 也无解，需要专用工具（如 yt-dlp 的 DRM 需要额外处理），不在本工具范围。

## 五、纯 Python 手动解密（不依赖 yt-dlp）

`../examples/download_video.py` + `../examples/refill.py` 展示了完整的手动流程：

1. 解析 m3u8 拿 `#EXT-X-KEY` 的 key URI + IV；
2. 下载 key 文件（伪装成 `.ts` 的 16 字节 key）；
3. 用 `cryptography` 的 AES-CBC 解密每个分片并去 PKCS7 padding；
4. 按序拼接成 `.ts`。

这只作为**教学/排障**用，日常直接用 yt-dlp 更快更稳。

## 六、关键经验（踩坑记录）

- **并发下载必须收集异常**：`concurrent.futures` 的 `as_completed` 循环若不调 `.result()`，分片下载失败会被静默吞掉，导致缺片。yt-dlp 自带重试，手动实现时务必「下载完比对缺失 + 重试补下」。
- **token 会过期**：m3u8 的签名链接（`xx.com/hls/<token>/...`）通常 1~2 小时内有效，自动化时每次重新解析 m3u8 拿最新 key/IV/分片列表。
- **UA 头必带**：`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0 Safari/537.36`。
- **cf_clearance 绑定 UA+IP**：Cloudflare 的 `cf_clearance` cookie 与「User-Agent + 出口 IP」绑定，用 `--cookies` 时务必同时 `--ua` 带一致的 UA、且出口 IP 一致，否则仍可能被拒。
- **本机环境雷区**：`pip install`、conda、winget 均可能因网络/代理污染卡死，yt-dlp 优先用 wheel 直下 + `sys.path` 引用，ffmpeg 用 gyan.dev 直连 zip。
